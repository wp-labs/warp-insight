## 18:55 **纠正上一轮的错误判断**：17:15 那次不是"卡死复发"，是整机重启

上一轮我把 `17:15:44 的 VictoriaMetric periodic push failed` 判为"同型复发 → 必然复现"。**错了。**
取证结果（可复核）：

| 证据 | 命令 | 结果 |
|---|---|---|
| 机器重启时刻 | `sysctl -n kern.boottime` | **Sun Sep 13 17:18:27**（`uptime` = up 1:36） |
| 容器停机/启动 | `docker inspect monitor-victoria-metrics-1` | FinishedAt **17:15:43** / StartedAt **17:21:27**（关机时先停，登录后 OrbStack 自启） |
| VM 全天启动次数 | `docker logs … \| grep -c "starting VictoriaMetrics"` | **2**（本地 09:55:16 与 17:21:27）→ **14:09 那次 VM 一直是活的** |
| 关机瞬间 | `pmset -g log` | 17:15:43 有 20 条 coreaudiod 断言批量释放（应用被终止） |

结论：**两次事件不同因**。
- **14:09–15:00（约 50 分钟）= 客户端卡死**（VM 在跑、端点健康、新进程能写 → 排除法指向长驻进程的
  keep-alive 连接半开后不复用新连接）。配置 `flush_secs=1 / timeout_secs=5`，失败却是 1 次/秒的**即时**错误
  → 不是写阻塞/超时，是内核立即报错却不换连接。**触发条件未证实**（当时的 OrbStack 进程已随重启消失）。
- **17:15:44–17:17:59（2 分 16 秒，136 次）= 关机过程的正确报错**：容器先被停（17:15:43），
  wparse 作为后台进程多活 2 分钟才被杀，报错是如实反映。**真正的问题是它没被自动拉起**
  —— 开机 17:18:27 → 17:32:40 手动启动，**14 分钟空窗**。

**本仓库可实现的两项修复**（wparse 源码不在本仓库，`wp_connectors` 是外部 crate）：
1. 给 wparse/agentd 加 **launchd 开机自启 + KeepAlive**（盖住"整机重启"这类场景）。
2. 加**外部守护**：`monitor.dat` 或 `wparse_send_to_sink` 连续 N 分钟不增长 → 重启 wparse（盖住客户端卡死）。
